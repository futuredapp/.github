## CodeCharta snapshots

`universal-codecharta.yml` generates code metrics and integrated dependency maps with CodeCharta 2.x. The default
analysis image is pinned to a fork build that includes experimental Swift dependency support. Stack profiles remain
`swift`, `kotlin`, `kmp`, `ft-fullstack` and `multi`; file-extension filters, exclusions and `git_log_since` still apply.

Consumers need a viewer that reads **cc.json 2.0** and a data-repository publisher that accepts maps without a
separate `.cg.json` graph. A viewer upgrade is required before switching a legacy deployment. The workflow requests
`packages: read` and authenticates using `GITHUB_TOKEN`; grant package access only if the selected private image
requires it. `analysis_image` accepts another compatible image, and `dependency_engine` selects native `codecharta`
or legacy `dependacharta` analysis. Swift dependencies require an image with the Swift dependency parser, such as
the default fork build. Its Swift resolution is experimental and structural; it does not run the Swift compiler.

```yaml
jobs:
  architecture:
    # Replace <published-version> with a release containing the native dependency workflow.
    uses: futuredapp/.github/.github/workflows/universal-codecharta.yml@<published-version>
    with:
      stack: multi
      data_repo: example-org/architecture-snapshots
      picker_base_url: https://architecture.example
    secrets:
      CODEBASE_ARCHITECTURES_TOKEN: ${{ secrets.ARCHITECTURE_DATA_TOKEN }}
```

PR events publish previews; pushes publish history and update latest pointers. Non-backfill manual runs publish
`<date>-run-<workflow-run-id>` entries, using the run date rather than the source commit's date. Their metadata
includes the trigger, creation time, source ref/commit and workflow URL so a compatible picker can list them
separately. Backfill remains source-only to avoid re-running the full analysis for each historical merge.

To retain the previous pipeline, set both inputs together:

```yaml
with:
  dependency_engine: dependacharta
  analysis_image: codecharta/codecharta-analysis:1.143.0
```

Existing `.cg.json` files and published legacy images remain useful for historical maps and rollback. This change
does not archive or delete them. On a map-only update, publication removes stale graph pointers so an older graph
cannot be mistaken for the new snapshot. Other historical graphs are retained.

Before publishing a release, use the normal ref-bump procedure below to pin the workflow's internal `@main` action
references to that release. Existing consumers pinned to older releases keep their existing pipeline until updated.

## Creating a new release

1. Bump all internal action refs to the new version:
   ```bash
   .github/scripts/bump-action-refs.sh 2.3.0
   ```
2. Commit and tag:
   ```bash
   git add -A
   git commit -m "Bump action refs to 2.3.0"
   git tag 2.3.0
   git push origin main --tags
   ```

The [`validate-release-tag`](.github/workflows/validate-release-tag.yml) workflow runs on every tag push and fails if any `futuredapp/.github` refs don't match the tag version.
